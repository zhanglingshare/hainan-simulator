# 海南岛产业风洞 · 十二角色研究争论台（HDC 1.0）

> 本文说明已实现的前台运行能力、科研边界，以及要升级成真正自主LLM Agent需要的后端条件。面向普通人的入口仍是十页产业模拟器，不新增“选择角色”的门槛。

## 0. 把“计算器”升级成“发现引擎”

研究目标不止是让用户改变一个增速、看GDP终值。真正需要交付五类价值：

1. **视野**：发现以前未曾注意的产业角色、服务与潜在连接；
2. **思维**：比较能够解释同一现象的竞争性假说，知道下一条反证应找什么；
3. **认知**：区分事实、统计口径、候选机制和现实政策效果；
4. **工具**：操作关系实验、双世界模拟、价值留存的识别集，而非被动阅读；
5. **灵感**：保留大胆而尚未证实的候选连接，以后可再审查。

设计红线：**建构时允许跳跃，验证时保留审查，输出时不得把H级假设冒充A级事实**。逻辑不是限制想象的理由，但想象不能取消他人质疑的权利。

## 1. 十二个角色，共用十张研究工作台

页面Agent均能使用同一个研究协议、证据表和其他角色的消息；区别不是能力被锁定，而是关注点和“怀疑本能”不同。

| 角色 | 主战场 | 优先研究 | 最怀疑什么 |
|---|---|---|---|
| 主持（全局） | 全站 | 显示分歧，决定交接 | 被平均掉的确定感 |
| 提问 | 01岛屿异动 | 跨指标矛盾如何重构问题 | 含糊与先验结论 |
| 数据 | 02产业史 | 版本、时间窗、人口与经济单位 | 没有出处与混用口径 |
| 关系 | 03产业关系 | 物流、采购、人才的候选边 | 把关联当真实交易 |
| 机制 | 04产业现场 | 为什么会出现这个现象 | 单一叙事 |
| 断崖 | 05价值留岛 | 资金、订单、回款与兑现 | 总量自动转化本地价值 |
| 反事实 | 06双世界 | 同条件下替代未来与副作用 | 把调参当政策效果 |
| 脆弱度 | 07压力风洞 | 断点、替代与组合条件 | 平均值代表稳定 |
| 风洞 | 08机制对抗 | 模型分歧与极端情形 | 点预测的虚假精确 |
| 测量 | 09忽略了什么 | 证据等级与研究准入 | 推断冒充观测 |
| 档案 | 10研究档案 | 退役、改判与研究回流 | 结论不可追踪 |
| 简报（全局） | 全站 | 用户能带走的新问题与行动桥梁 | 无条件建议 |

## 2. 五种消息（已实现）

每条消息至少包含：\`id\`、\`type\`、\`claim\`、\`agent\`、\`target\`、\`tier\`、\`refs\`、\`parentId\`、\`date\`、\`text\`。

- **发现**：提出建构性候选机制，并注明来自哪个公开观察；
- **质疑**：点名另一角色，指出跨口径、因果、测量或证据缺口；
- **异见**：不使用多数投票或“平均结论”隐藏竞争解释；
- **交接**：写明下一页最值得核验的具体数据，链接携带\`claim\`；
- **改判**：写入新状态与明确理由，原有消息不得被删除。

**退役不是第六种消息**，而是“改判”的一种状态。不同意见和退役假说作为研究记忆长期保留。一个错误不能因为醒目就加分，只有指出了可验证的新问题才有价值。

## 3. 两只手如何工作

**建构之手**在给定现实信号后，允许产生跨领域类比、反常识、不同主体的潜在关系，保留H级假说和后续可验证问题。

**验证之手**不急于删去想象，而是挑战统计口径、提出竞争解释、查看原始来源，标记当前无法识别的关系。模型计算不能凭借一万次随机重复，把未经标定的假设变成现实发生概率。

当前内置8条人工编写的研究种子：贸易与专业服务、工业与投资错位、旅游收入、农产加工、隐藏生产性服务、统计版本、情景模型识别、产业网络断点。每个种子都有建构、异见、审查、验证任务，以及用户获得的五类价值。

## 4. 已有工作流（无需登录即可使用）

1. 在任意十页入口打开“本页研究Agent”。
2. 默认显示本页Agent的观察使命与最值得争论的问题；首次进入本页，浏览器会按照规则协议生成一轮**可核对的模拟辩论**。
3. 点击“召开一轮研究争论”进一步展示四种消息；也可点“专门反驳”“跨域再想一种可能”“让异见发言”。
4. 看到证据时，展开统计指标、时间窗与官方原始来源；遇到候选机制，保持H或C级。
5. 通过“交接”进入另一工作台，保留同一条问题ID；“我得到了什么”页面具体显示视野、思维工具、认知升级、灵感、核验动作。
6. 玩家可以提出自己新的候选假说，默认H级，转交测量Agent；改判必须填写理由。原消息不抹掉。
7. 在“研究留痕”导出\`JSON\`，包括本地事件、候选假说、退役和改判历史。

所有内容暂存在本机浏览器\`localStorage\`；换设备、清缓存或浏览器存储受限时无法跨设备恢复，因此应主动导出日志。

## 5. 科学与工程界限

**当前确实运行的是：** 静态页面上的确定性、多角色研究协议和有结构的争论生成器。每个角色有独立的怀疑原则，但现有“候选连接”和“竞争解释”由人工预先设置，并不是多个大语言模型各自调用不同工具、实时收集全网证据或自主提出完全新机制。

**当前尚未实现：** 实时LLM推理、跨网页自主研究、可证实的信息获取、实际企业采访、持续后台Agent运行、真实预测锦标赛、跨用户协作和外部消息发送。网站不要求用户提供API密钥；更不会在公开前端存储私钥。

**要升级为真正自主Agent**，需要一个独立托管的鉴权网关：
- 服务端按不同Agent的“使命/建构/验证/异见”分开调用具工具能力的大模型；
- 每次从检索和行业数据工具获取独立证据，强制引用原文、时间窗、观察单位及来源版本；
- 生成按协议验证的五种结构化消息，不允许无来源的数字直接升级A级；
- 多角色可独立提出假说并互相异议，审计Agent单独接入资料交叉核验；
- 事件日志、原始引用、模型版本、修改理由在服务端可回放；不拿用户隐私数据去做公开讨论；
- 提供成本、权限、超时、速率限制及错误恢复机制；
- 在安全网关上线与API权限确认之前，维持本地可审计规则工作流而不是伪装成在线模型。

## 6. 怎么判断有没有交付价值

不要只统计消息数、Agent数、模型数和页面访问时长。

建议验证五项任务：
- 没有专业训练的普通用户，能否用自己的话准确描述一个反常识信号？
- 用户能否区分“事实”与“模型大胆猜测”？
- 能否提出一个足够具体、可以进一步验证的新连接？
- 一次异见是否能使用户改变判断或发现新的关键数据？
- 最后能否带走一条真实可行动的研究问题，而不是一句空泛建议？
